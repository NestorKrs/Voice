# Voice

Voice is the owner's personal, browser-only text-to-speech reader (React + Vite, NO backend). The owner pastes very long text (35 to 50+ pages). The app reads it aloud chunk by chunk with free OpenRouter models (Fish Audio S2.1 Pro Free and HeyGen Voice Turbo Free). You are the only writer of the code. The owner runs the app, builds, lints, commits and tests live.

## Quick map (as of 2026-11-09; docs/codebase-map.md wins if it differs)

- src/App.jsx: the whole page in ONE big component (state, handlers, top bar, Text/Reader/Job panels, player bar, Settings drawer, status bar) plus two module-level controls (FontWeightControl, TextReadView). Most edits and most breakages happen here. src/highlight.js picks the word/sentence range and the weighted character index for the Text panel's read-only highlight view (highlightRange, sentenceRanges, charWeights, charAtFraction) (textarea hidden while playing); the status bar shows the selected-character count at its right end; the Reader pane has a Download icon button on each chunk row (MP3/WAV from Settings) and, pinned below the scrolling chunk list, the buttons 'Download all chunks' (ZIP) and 'Download all joined'; clicking a chunk row jumps the player there. A floating speaker icon appears at the top-right corner of a text selection and reads just that selection aloud.
- src/silenceMap.js: pure pause finder for decoded chunk audio (RMS frames, relative threshold, leadIn/tail). src/timeMap.js: turns those pauses into a playback-time -> character-index map (n-1 longest pauses). src/alignMap.js: aligns the text's punctuation breaks to the real pauses by dynamic programming, so a break may be skipped and one wrong pause cannot shift every later break. All three: see references/highlight-pauses.md.
- src/App.css (layout) and src/theme.css (colors, button look; CSS variables --bg --panel --line --muted --accent --ease --font).The font is @font-face in src/theme.css.
- src/panelLayout.js: panel order (drag by grip; the page changes the visual order with CSS order, the DOM order stays fixed). src/panelWidths.js: panel widths in percent, limits, handles.
- src/providers.js: provider list (Fish, HeyGen, owner-added), only models ending in :free. src/audioFormat.js: PCM to WAV, audio type detection.
- src/speechClient.js: the ONLY file that uses the network. src/wiring.js: the ONLY file that imports readKey; builds the services (cache, speak, counter, makeKey).
- src/scheduler.js: makes chunks ahead of the playhead (window = playhead + lookahead), pauses on the daily cap. src/audioCache.js: IndexedDB. src/requestCounter.js: requests per UTC day.
- src/playerEngine.js and src/playerCore.js: the bottom player (two Audio slots, preloads the next chunk, reset()).
- src/settingsStore.js: settings, key and text in localStorage. Settings keep one voice per provider; "voice" is the active provider's voice.
- src/textPipeline.js (clean and split text), src/textStats.js (counts).
- src/textFind.js (findMatches/nextIndex) and src/textScroll.js (scrollTextareaToIndex) power the Text panel's find row above the textarea.
- File loading (drop a file onto the Text panel, or the Load button): FileReader.readAsText only; the file input accepts .txt,.md,text/plain, and a shared name guard (src/fileTypes.js textFileRejection, imported into App.jsx) rejects any other lowercase name with "Cannot load <name>: Voice reads only .txt and .md files." in the notice and the status bar. Only plain text is supported; .doc, .docx and .pdf are out of scope. Dropping a file cancels the scheduler, clears the audio cache and resets the player; the Load button only sets the text. Chunk download: src/chunkDownload.js (chunkFileName, audioKind, toWavBytes, encodeWav, convertChunk), src/mp3Encoder.js (lazy lamejs), src/zipStore.js (createZip/zipChunks), src/joinAudio.js (stripId3, wavHeader, wavParts, joinMode, sameAs); the row Download button and the Reader pane's 'Download all chunks' / 'Download all joined' buttons save through window.showSaveFilePicker with a Blob + <a download> fallback (see references/download.md).
- Hosting: the site serves the app at thefivefigures.com/voice/app/ (see Build base above).
- index.html holds the app shell and the browser-tab icons; public/ holds the icon files (icon.svg, favicon.ico, apple-touch-icon.png). public/ is NOT in vship's staged path list, so a commit that adds or changes an icon file needs an explicit `git add public/...`.

## Standing rules (every task)

1. No written task means no work. Do exactly the numbered steps, in order. One task per message.
2. Touch only the files the task names. A file the task does not name stays untouched, even for a one-line tidy. No refactors, no renames, no extra features, no cleanup. Never delete or replace existing UI unless the task says so. New things are additive.
3. If a step fails, is unclear, or an anchor is not found exactly once: STOP. Paste the RAW output. Wait for the owner. Do not guess, do not work around it. An anchor is any line or text the task tells you to replace or insert next to. Exception: a task that names an exported constant, helper, ref or element handle the code does not have is a task-text mistake, not a blocker; when another step of the same task requires it (a focus + setSelectionRange step needs a ref), the shape is obvious from the file's own defaults — add it and say so in the report. Only stop when the missing anchor is a decision only the owner can make.
4. Paste RAW command output, never a summary. Write NOT RUN for a command you did not run. Never invent output. Never say something works unless you ran a check and pasted its output. Tests with mocks do not prove the live app works.
5. Bugs: first a read-only diagnosis. A diagnosis task changes no file. Paste the code and the raw evidence, answer each lettered question in one line, in order, with the line number that proves it, and name the root cause and the failure layer. An orient step that asks lettered questions is answered the same way: one line each, with the proving line number. "Not found in code" is a valid answer; a guess is not. A summary instead of the raw output is a failed step. Fix only after the owner says go, or when the task itself says to fix if the evidence matches the condition it states.
6. Never weaken or edit an existing test to make it pass. If an old test breaks only because of a field your task introduced, change only that expected value and say which test. This includes a deepEqual literal that must now carry the new default field, even when the task says "append only" to that test file.
7. Add no dependency. Never edit the dependency lists in package.json. If one is needed, tell the owner the package name. AGENTS.md no longer names any pre-approved package, so treat every new dependency as needing the owner's explicit yes.
8. Secrets: never ask for, open, print or log the API key or any .env file. When you need network facts from the owner, ask for the Network tab Payload and Response only, never Headers.
9. Money and cap: only models whose ID ends in :free (code enforces it). The free cap is 50 requests per UTC day, or 1000 once the owner's lifetime credit purchases reach $10 (the owner bought $10 and confirmed the 1000 cap; the Daily limit setting is chosen by hand), plus 20 requests per minute. The cap is shared with other free models and every attempt counts, including failed ones. The browser cannot read X-RateLimit-Reset, so a cap pause falls back to the next 00:00 UTC. Never make a live request. Never write code that loops requests. Never tell the owner to press Retry repeatedly.
10. Never log pasted text or chunk text. Diagnostics hold time, chunk number, status and latency only.
11. UI: dark theme. Every disabled control shows its exact reason (visible text or title; when a task asks for both on an input, the visible text is a small span in the same row, because an input cannot render arbitrary visible text). Every failure shows an exact reason on screen and in the status bar. No modals and no toasts for errors. Every click gives visible feedback. The bottom status bar and its expandable event log keep their markup and behavior; the owner copies logs from there. Change them only when a task says so.
12. Replies: short, plain words.
13. Lint: add no new lint warnings. No unused variables, functions, imports or parameters. If a parameter must stay unused, start its name with an underscore. The owner's vship run prints the warning count.
14. When the owner calls a task "quick", "mini" or "small", implement the smallest direct version that works; add no optional settings, abstractions or speculative guards, only the minimum needed for correct behaviour.

## Editing big files (App.jsx is one big component, hundreds of lines)

Hermes has broken this file by pasting a function inside another function, by declaring a name twice, and by skipping a step. So:

- Insert at the exact anchor the task gives. If the task gives none: put new component-level functions directly above `const panelClass =` (grep that it exists first) and new hooks next to the other hooks. New module-level components go next to FontWeightControl, above `export default function App()`.
- New component-level const lines are indented exactly 2 spaces. A function indented deeper than 2 spaces is inside another function and is WRONG.
- An effect's dependency array may only name values declared ABOVE the effect. App.jsx declares its derived values near the bottom (`const reading`, `const readChunk`), so listing one in a deps array evaluates it during render, before initialization: the whole App crashes with a temporal dead zone error and a black screen. Inline the condition in the effect body instead (`const isReading = playerState.total > 0 && (playerState.status === 'playing' || playerState.status === 'paused')`) and list only state fields.
- A task that says existing code must stay "byte for byte" means the bytes, indentation included. Do not wrap those lines in a new `if`/`else` block: the extra indent changes them. Compute both branches flat and select at the end (`const mapped = ...;` then the existing lines unchanged, then `const offset = mapped ? a : b;`), and `diff` the block against a copy of the original text to prove it.
- After editing, run this and paste the result (expect no output except the last word):
  (grep -oE "^  const [A-Za-z0-9_]+" src/App.jsx | sort | uniq -d); echo "dup check done"
- The dup check has two known pre-existing false positives, and the grep matches 2-space-indent consts inside the module-level components too, not only inside App: `const chunks` (once inside handleStart, once at component level) and `const commit` (FontWeightControl and LeadingControl). Expect both before `dup check done`. Neither is your edit; do not "fix" the indentation unless the task says so.
- When a task says "after EVERY such line", grep the anchor first and count occurrences; the same line can appear at different indentation (for example `schedulerRef.current = null;` at 8 and 10 spaces). Patch each occurrence with its surrounding context, not replace_all.
- When a task says "append only" to a test file, append with a heredoc (`cat >> tests/x.test.mjs <<'EOF'`); never rewrite the file or reorder existing tests. A new `import` line may ride along in the heredoc: ESM imports hoist, so appending `import { x } from '../src/y.js';` at the bottom works and leaves every existing line untouched.
- Print the 6 lines before and after each insertion with sed -n and paste them.
- Re-read each changed block once for unbalanced braces and parentheses. The patch tool's fuzzy match can insert the leading indentation of old_string into the middle of a line; when patching a line-internal substring, keep old_string/new_string free of leading indentation and re-read the line after patching.
- Do every numbered step. A skipped step is the most common failure. Finish with the wiring proof.

## Finding the failure layer (bugs)

Name which layer fails before proposing a fix:
(a) wiring: a function or handler is not reachable, or never called;
(b) UI state: a handler or effect uses an old copy of state (stale closure, stale cached data);
(c) logic module: scheduler, cache, player engine, settings store, text pipeline;
(d) provider response: HTTP status and the exact message from OpenRouter;
(e) browser behavior: autoplay blocking, passive event listeners, native drag images, the Brave app window, page zoom;
(f) dev tooling: Vite showing an old or broken module (a syntax error in the terminal output).
If you must ask the owner, ask ONE question that separates two layers, for example what the status bar line says, or the Payload and Response of the failed speech request.
Static layout blockers (fixed widths, missing @media breakpoints, a grid that never collapses, no flex-wrap) are authoring-time CSS/JSX, not a runtime failure: they belong to none of (a)-(f), so say so instead of forcing them into (e). Only touch- and viewport-specific items are (e) browser behavior.

## Known pitfalls (each came from a real failure or a checked browser behavior)

- A function was pasted inside handleStart, so the dropdown could not find it. -> Follow "Editing big files"; check the indentation.
- A CSS animation on `width` does not override an inline `width` style, so an indeterminate loader stays stuck at the inline value. -> Set the element's base width to 0% and let the keyframes animate to 100% (or remove the conflicting inline width), otherwise the animation has no visible effect.
- A task step was skipped and the work was reported as done. -> Do every step; the wiring proof must show definition and use.
- The player kept the old audio after the provider changed, and dropping a new file had to clear the cache by hand. -> Anything that keeps loaded or cached state (player slots, scheduler window, schedState, audio cache) must be reset when its inputs change (provider, voice, chunk size, text, a loaded or dropped file). Ask: what stale copy does this keep?
- React onWheel and touch handlers are passive, so preventDefault does nothing and the browser zooms the whole page. -> Use a native addEventListener("wheel", fn, { passive: false }) inside an effect on the element, and remove it in the cleanup.
- The OS save dialog was opened after an await (after conversion or ZIP building). -> The browser only allows window.showSaveFilePicker synchronously inside the click handler; open it first, before any async work, then convert and write the file.
- The agent stopped to ask the owner to run a check or to confirm a step before finishing. -> The owner tests live in person; implement the task fully, then list what they must test under Not verified.
- Retry reused the voice and provider from the first Start Reading. -> A handler must read current settings, or the owner must start again; say which.
- The switch stayed disabled after an error. -> Disable controls only for the shortest real reason, and show that reason.
- Audio from different providers has different formats. -> Pick the audio type from the bytes (audioMime), never hardcode audio/mpeg. audioMime returns only 'audio/wav' or 'audio/mpeg', so it cannot tell raw PCM from MP3; a function that must return 'pcm' needs its own MP3 frame-sync/ID3 check on top of audioMime.
- Pasting 150,000 characters must stay smooth. -> Keep typing state local and debounced; never re-render the whole chunk list on every key press.
- Eleven catch blocks were written as "catch {" but used the variable e, so any real error showed "e is not defined" and hid the cause. -> Always write catch (e) when the block uses e. A test (tests/app_catch.test.mjs) scans App.jsx for this.
- Code was added that nothing calls (an unwired engine), which added 5 lint warnings and made a commit message untrue. -> New code is only done when something imports and uses it; the wiring proof must show that, unless the task says a later stage will consume the module (then the test import is the proof).
- A task swaps one module for another in App.jsx (for example buildTimeMap for alignTimeMap). -> Remove the now-unused import from App.jsx, because an unused import is a lint warning, but leave the old module and its test in the tree: the task names only App.jsx, the tests still import it, and deleting it is scope creep. Say in the report that the old module is now dead code in the app.
- The cache passed its tests, but the IndexedDB store returned a record object while the memory store returned bytes, so saved audio read back as "no audio in cache" (the row said ready, Play found nothing). -> Every store follows one contract (get returns the bytes or null, never a record object), and tests also use a fake store shaped like IndexedDB, not only the memory store.
- An IndexedDB write was reported as done when its request succeeded, before the transaction committed. -> A write is finished only when the transaction completes; reject on error or abort.
- A one-line tidy was made in a file the task did not name (wiring.js, the file that reads the key). -> A file the task does not name stays untouched. Describe what you saw in the report instead.
- The backup counter was reset by the agent itself. -> Only the owner's backup message resets it.
- The backup counter is cumulative since the last backup. -> Once it is 3 or more, write BACKUP DUE at the top of the report; a counter well above 3 is past due, not 'not yet due'.
- Diagnosis questions were answered with a summary, so the cause could not be checked. -> Answer each lettered question in one line with line numbers, and paste the raw output.
- A speed slider with step 0.25 reached 1.75, a value the player does not accept, so the thumb snapped back, and its label changed width as the number changed. -> A control for a fixed list of values moves by position in that list (import the list, never copy it) and its label has a fixed width. Do not hide jumpiness with a debounce or a transition.
- A finder that jumps on every keystroke steals focus from its own input, so typing is interrupted. -> Compute the current match from the caret in the change handler and setSelectionRange there WITHOUT focus(); on Enter/Next/Previous focus the textarea, setSelectionRange and scroll by hand, and leave focus in the textarea (the owner steps with the buttons after the first press; Enter in the textarea inserts a newline by design).
- Chrome/Brave do not scroll a textarea to a programmatic setSelectionRange, and an unfocused textarea paints the selection in the faint inactive colour. -> For a find box, scroll by hand: measure the text up to the match in a hidden mirror div with the textarea's computed font, padding and clientWidth, then set ta.scrollTop to centre the match (src/textScroll.js); give the textarea a ::selection rule so the active selection is unmistakable, and never return focus to the find input after a jump, or the jump looks dead.
- The highlighted chunk row came from its own state that only the row's Play button set, so Previous and Next never moved it. -> Derive what the screen shows from the engine state (activeRowIndex); never keep a second copy of what the engine already knows.
- A message the task says to show "in the row" needs its own per-row state keyed by chunk index; the shared notice renders only in the player bar, and a per-row note must be cleared on success.
